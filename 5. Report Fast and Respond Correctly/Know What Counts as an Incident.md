### Goal

A cybersecurity incident can be defined as an event that impacts the organization and prompts response and recovery; technically it can be considered an event that actually or potentially jeopardize confidentiality, integrity, or availability. 

Incidents include suspicious messages, malicious links, exposed credentials, accidental data disclosure, misdirected emails, lost devices, malware warnings, unusual account activity, suspected fraud, and unauthorized access. Overall we emphasize reporting cyber incidents, phishing attempts, malware, and vulnerabilities. Generally, when in doubt, report.

### Learning Objective

By the end of this section, we will understand what kinds of events may count as cybersecurity incidents or warning signs, and why fast reporting is more important than being certain.

Employees should learn this core behavior:

**If something seems suspicious, risky, exposed, compromised, or wrong, report it quickly. Do not wait until you are sure.**

Managers and executives should learn this assurance principle:

**The company must define what employees should report and make reporting simple, safe, and fast.**

### Why This Matters

Many incidents become worse because people wait too long to report them.

**Employees may delay because they think:**

- “It was probably nothing.”
    
- “I do not want to bother IT.”
    
- “I might get in trouble.”
    
- “I already closed the page.”
    
- “The email looked suspicious, but I did not click.”
    
- “I clicked, but nothing happened.”
    
- “Someone else probably reported it.”
    

**This delay gives attackers more time.**

A fast report can help the company block malicious links, reset credentials, isolate devices, remove bad emails, warn other staff, contain malware, and reduce damage.

### Core Rule

An incident does not need to be a confirmed breach before employees report it.

The reporting rule is:

**Report suspicious activity, mistakes, possible exposure, and confirmed incidents. Let the response team decide severity.**

Employees are not expected to investigate or prove the incident. They are expected to report quickly.

### What Counts as an Incident or Reportable Event?

Employees should report the following.

#### 1. Suspicious Messages

**Report:**

- Phishing emails
    
- Suspicious attachments
    
- Suspicious links
    
- QR-code login requests
    
- Fake invoice messages
    
- Executive impersonation
    
- Vendor bank-detail changes
    
- Requests for passwords or MFA codes
    
- Messages asking for secrecy or urgent action
    

Even if nothing was clicked, the message may be targeting other employees too.

#### 2. Clicking or Opening Something Suspicious

**Report if you:**

- Clicked a suspicious link
    
- Opened an unexpected attachment
    
- Scanned a suspicious QR code
    
- Downloaded a file from an unusual source
    
- Entered credentials into a suspicious page
    
- Approved an MFA prompt unexpectedly
    
- Replied to a suspicious request
    

Do not hide the mistake. Fast reporting is the correct action.

#### 3. Account Warning Signs

**Report:**

- Unexpected MFA prompts
    
- Password reset emails you did not request
    
- Login alerts from unfamiliar locations
    
- Emails sent from your account that you did not send
    
- New forwarding rules you did not create
    
- Missing or changed account settings
    
- Unusual app permission requests
    
- A coworker receiving strange messages from your account
    

These may indicate account compromise.

#### 4. Device Warning Signs

**Report:**

- Security warnings
    
- Strange pop-ups
    
- Browser redirects
    
- Files renamed, missing, encrypted, or changed
    
- Unusual slowness or crashes
    
- Unknown programs or browser extensions
    
- Disabled security tools
    
- Unexpected remote access prompts
    
- Ransom messages
    
- Repeated update failures
    

Do not try to clean the device yourself unless instructed.

#### 5. Data Exposure or Sharing Mistakes

**Report if:**

- You sent data to the wrong person
    
- You shared the wrong file
    
- You gave access too broadly
    
- You created a public link by mistake
    
- You uploaded sensitive data to an unapproved tool
    
- You pasted confidential information into an unapproved AI tool
    
- You forwarded a thread containing sensitive information
    
- You lost a printed document or storage device
    

A data mistake is reportable even if it was accidental.

#### 6. Lost or Stolen Devices

**Report immediately if a company device is:**

- Lost
    
- Stolen
    
- Left in a public place
    
- Taken by an unauthorized person
    
- Damaged in a way that may expose data
    
- Accessed by someone who should not use it
    

This includes laptops, phones, tablets, USB drives, security keys, ID badges, and access cards.

#### 7. Fraud or Business Process Manipulation

**Report suspicious requests involving:**

- Payments
    
- Bank-detail changes
    
- Payroll changes
    
- Vendor updates
    
- Gift cards
    
- Confidential documents
    
- Contract changes
    
- Delivery redirection
    
- Account recovery
    
- Help-desk requests
    
- Executive instructions that bypass normal procedures
    

Business fraud attempts are cybersecurity-relevant when they use digital identity, email, messaging, accounts, or social engineering.

#### 8. Unauthorized Access

**Report if:**

- You can access data you should not see
    
- Someone asks to use your account
    
- A former employee appears to still have access
    
- A contractor still has access after a project ends
    
- A shared folder includes unexpected external users
    
- An unknown user appears in a system or file
    
- A third-party app is connected unexpectedly
    

Unnecessary access is not harmless. It can become an incident if misused.

### Report Even If You Are Not Sure

Employees should not try to classify the incident themselves.

Use this simple test:

**Could this involve unauthorized access, data exposure, fraud, malware, account compromise, device loss, or violation of security procedures?**

If yes, report it.

A false alarm is better than a hidden incident.

### What Employees Should Do

**Employees should:**

1. Stop the risky activity.
    
2. Do not click further, reply further, or approve prompts.
    
3. Preserve the message, file, device, or evidence.
    
4. Report through the approved channel.
    
5. Explain what happened clearly.
    
6. Say whether they clicked, opened, replied, downloaded, entered credentials, or approved MFA.
    
7. Follow instructions from IT, security, management, legal, or HR.
    

### What Employees Should Not Do

**Employees should not:**

- Wait until they are certain
    
- Hide mistakes
    
- Delete suspicious messages before reporting
    
- Try to investigate alone
    
- Install cleanup tools
    
- Wipe or reset the device without instruction
    
- Forward suspicious files to coworkers
    
- Continue using a possibly compromised account or device for sensitive work
    
- Assume someone else already reported it
    
- Downplay the event because they feel embarrassed
    

The worst response is silence.

### Manager Responsibilities

**Managers should:**

- Encourage fast reporting.
    
- Avoid blaming employees for honest mistakes.
    
- Know the company’s reporting channel.
    
- Escalate suspected incidents immediately.
    
- Support employees who need to stop work during investigation.
    
- Make sure contractors and temporary staff know what to report.
    
- Treat near-misses as learning opportunities.
    
- Never pressure employees to hide or minimize incidents.
    

Managers should create the culture where reporting is normal.

### Executive and Key Staff Assurance Points

Executives and key staff should verify that the company has a clear incident reporting standard.

**Leadership should ensure the company has:**

- A written definition of reportable cybersecurity events
    
- A simple reporting channel
    
- An emergency escalation path
    
- A no-blame reporting culture for honest mistakes
    
- Training on what to report
    
- Role-specific examples for finance, HR, managers, executives, and IT
    
- A way to track reported events
    
- A process for triage and escalation
    
- A process for legal, privacy, insurance, or regulatory review when needed
    

The leadership question is:

**Do employees know what to report, and will they report quickly without fear?**

### Key Takeaway

An incident is not always obvious at first. Suspicious messages, clicked links, unexpected MFA prompts, lost devices, data-sharing mistakes, account warnings, and fraud attempts may all require reporting.

Employees should not decide alone whether something is serious. Report quickly and let the response team assess it.

**Fast reporting is protection. Delay is risk.**
