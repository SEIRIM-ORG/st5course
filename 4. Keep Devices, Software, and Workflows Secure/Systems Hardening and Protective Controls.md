### Goal

While employees only need the “do not bypass controls” behavior, managers and executives need to verify baseline configurations, endpoint protection, email/web filtering, logging, and exceptions.

This section focuses on the company-level controls that keep devices, software, and workflows secure. These include protective outcomes for platform security, configuration management, data protection, identity/access, and technology resilience.

### Learning Objective

By the end of this section, we will understand that secure devices and systems require more than updates. They also require safe configurations, protective tools, restricted access, monitoring, and controls that employees do not bypass.

Employees should learn this core behavior:

**Use company systems as configured. Do not disable, bypass, or weaken protective controls.**

Managers and executives should learn this assurance principle:

**The company must define, apply, monitor, and maintain secure baseline configurations and protective controls across its devices, systems, and workflows.**

### Why This Matters

A device can be fully updated and still be insecure if it is poorly configured.

**Examples of weak configurations include:**

- Users having local administrator rights unnecessarily
    
- Security software disabled
    
- Firewalls turned off
    
- Unapproved remote access enabled
    
- Weak screen-lock settings
    
- Old accounts left active
    
- Unnecessary software installed
    
- Browser extensions uncontrolled
    
- Cloud storage shared publicly
    
- Logs not collected
    
- Default passwords still in use
    
- Sensitive files stored locally without protection
    
- Email security controls missing
    
- USB devices allowed without control
    

System hardening means reducing unnecessary risk by configuring devices, applications, and workflows securely before attackers can exploit them.

### Core Rule

Secure systems should be configured to allow necessary work and block unnecessary risk.

**That means:**

- Turn on needed protections.
    
- Turn off unnecessary features.
    
- Remove unnecessary software.
    
- Limit administrator access.
    
- Restrict risky behavior.
    
- Monitor important activity.
    
- Review exceptions.
    

Hardening is not about making work impossible. It is about removing avoidable exposure.

### What “Hardening” Means

System hardening is the process of making devices, software, and services safer by reducing their attack surface.

The attack surface is everything an attacker might use to get in, move around, steal data, or disrupt the company.

**Hardening may include:**

- Disabling unused services
    
- Removing unnecessary software
    
- Enforcing screen locks
    
- Requiring encryption
    
- Limiting administrator rights
    
- Configuring firewalls
    
- Controlling USB devices
    
- Enforcing browser security settings
    
- Restricting macros or scripts
    
- Applying secure email settings
    
- Blocking known malicious websites
    
- Managing cloud-sharing settings
    
- Enabling logs and alerts
    
- Applying secure configuration baselines
    

The practical idea is simple:

**If a feature is not needed and creates risk, it should be disabled, restricted, or monitored.**

### Protective Controls Employees May Notice

**Employees may see or interact with protective controls such as:**

- Antivirus or endpoint protection
    
- Endpoint detection and response
    
- Web filtering
    
- Email filtering
    
- Spam and phishing warnings
    
- MFA prompts
    
- Password manager requirements
    
- Screen-lock policies
    
- Device encryption
    
- VPN or secure remote access
    
- Browser extension restrictions
    
- USB restrictions
    
- Software installation restrictions
    
- Blocked websites
    
- Restricted admin rights
    
- Cloud-sharing controls
    
- Data loss prevention warnings
    

These controls may sometimes feel inconvenient. But they are there to reduce risk.

Employees should not try to bypass them.

### What Employees Should Do

**Employees should:**

1. Use devices and software as configured by the company.
    
2. Keep security tools enabled.
    
3. Follow screen-lock and device-lock rules.
    
4. Use approved remote access.
    
5. Use approved browsers and extensions.
    
6. Follow cloud-sharing restrictions.
    
7. Report blocked activity if it affects legitimate work.
    
8. Ask IT for help instead of bypassing controls.
    
9. Report security warnings.
    
10. Avoid requesting administrator rights unless truly required.
    

### What Employees Should Not Do

**Employees should not:**

- Disable antivirus or endpoint protection
    
- Turn off firewalls
    
- Install unauthorized remote-access tools
    
- Use personal cloud storage to avoid restrictions
    
- Use personal email to bypass file-sharing controls
    
- Use unapproved browser extensions
    
- Change security settings without approval
    
- Use administrator rights for routine work
    
- Ignore data loss prevention warnings
    
- Store restricted files locally without approval
    
- Work around blocked websites using personal devices
    
- Pressure IT to remove controls permanently for convenience
    

If a security control blocks legitimate work, escalate the business need. Do not bypass the control.

### Common Protective Controls Explained

#### 1. Endpoint Protection

Endpoint protection helps detect and block malware, suspicious activity, and unsafe behavior on laptops, desktops, and sometimes mobile devices.

**Employee rule:**

Do not disable it. Report warnings.

#### 2. Firewalls

Firewalls help control network traffic and reduce unauthorized access.

**Employee rule:**

Do not turn off firewall protection or install tools that create unmanaged access.

#### 3. Device Encryption

Encryption helps protect data if a laptop, phone, or drive is lost or stolen.

**Employee rule:**

Use approved devices and report lost devices quickly.

#### 4. Screen Lock

Screen locks prevent unauthorized use when a device is unattended.

**Employee rule:**

Lock the screen when stepping away.

#### 5. Restricted Admin Rights

Administrator rights allow users to install software and change settings. Too many admin users increase risk.

**Employee rule:**

Use standard accounts for normal work. Request admin access only when justified.

#### 6. Email and Web Filtering

Email and web filters reduce exposure to phishing, malware, and known malicious websites.

**Employee rule:**

Do not try to bypass blocked links or warnings.

#### 7. Cloud-Sharing Controls

Cloud controls limit public links, external sharing, downloads, and permissions.

**Employee rule:**

Share data through approved methods and permissions.

#### 8. Logging and Alerts

Logs help the company investigate incidents and identify suspicious activity.

**Employee rule:**

Do not delete or alter evidence after a suspected issue. Report quickly.

### Manager Responsibilities

Managers should support protective controls instead of treating them as IT obstacles.

**Managers should:**

- Reinforce that controls should not be bypassed.
    
- Escalate legitimate business needs through approved channels.
    
- Avoid asking staff to use personal tools to avoid restrictions.
    
- Make sure team workflows work inside approved systems.
    
- Review repeated control exceptions affecting their team.
    
- Ensure contractors follow the same security expectations.
    
- Support standard user accounts instead of routine admin rights.
    
- Encourage employees to report warnings and blocked activity.
    

Managers should not normalize workarounds. A workaround may solve today’s inconvenience and create tomorrow’s breach.

### Executive and Key Staff Assurance Points

Executives and key staff should verify that system hardening is defined, applied, and maintained.

**Leadership should ensure the company has:**

- Secure configuration baselines
    
- Endpoint protection coverage
    
- Firewall controls
    
- Device encryption
    
- Screen-lock enforcement
    
- Restricted administrator rights
    
- Approved remote-access controls
    
- Email security controls
    
- Web filtering where appropriate
    
- Cloud-sharing restrictions
    
- Browser extension controls
    
- Logging and alerting
    
- Backup protection controls
    
- Exception tracking
    
- Periodic configuration reviews
    

The leadership question is:

**Are our systems securely configured by default, and do we know when protections are missing or bypassed?**

### Questions Leaders Should Ask

Executives and key staff should ask:

1. Do we have secure baseline configurations for laptops, servers, cloud systems, and key applications?
    
2. Are endpoint protection tools deployed across all company devices?
    
3. Are local administrator rights restricted?
    
4. Are devices encrypted?
    
5. Are screen-lock settings enforced?
    
6. Are firewalls enabled and managed?
    
7. Are remote-access tools approved and controlled?
    
8. Are email and web protections in place?
    
9. Are cloud-sharing settings restricted?
    
10. Are logs collected and reviewed for important systems?
    
11. Are exceptions documented and time-limited?
    
12. Are configurations reviewed after major changes?
    
13. Are managed service providers reporting control coverage?
    
14. Are controls tested or validated periodically?
    

### Evidence Leaders Should Request

**Useful evidence includes:**

- Secure configuration baseline
    
- Endpoint protection coverage report
    
- Firewall status report
    
- Device encryption report
    
- Local administrator rights report
    
- Screen-lock policy report
    
- Remote-access tool inventory
    
- Email security configuration summary
    
- Web filtering report
    
- Browser extension inventory
    
- Cloud-sharing configuration report
    
- Logging and alerting coverage report
    
- Exception register
    
- Configuration review records
    
- Managed service provider security reports
    

Leadership should not accept “we have tools installed” as enough. They should ask whether controls are deployed, enforced, monitored, and reviewed.

### Warning Signs of Weak Hardening

**The company may have weak hardening if:**

- Employees routinely have local admin rights
    
- Security tools can be disabled by users
    
- Devices are not encrypted
    
- Old remote-access tools are still installed
    
- Browser extensions are uncontrolled
    
- Public cloud links are common
    
- Logs are not collected
    
- Exceptions never expire
    
- Firewalls are unmanaged
    
- Unsupported software remains in use
    
- Employees use personal tools to bypass restrictions
    
- Managers pressure IT to remove controls permanently
    
- Nobody reviews configuration drift
    

Configuration drift means systems slowly become less secure over time as settings change, exceptions accumulate, and controls are not reviewed.

### Key Takeaway

Updates fix known weaknesses. Hardening reduces avoidable exposure.

Employees should use systems as configured and avoid bypassing controls. Managers should support secure workflows and escalate legitimate needs properly. Executives should verify secure configurations, endpoint protection, encryption, restricted admin rights, email/web defenses, cloud controls, logging, and exception management.

**A secure system is not only patched. It is configured to resist misuse, mistakes, and attack.**
