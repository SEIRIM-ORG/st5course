### Install Updates and Restart Promptly

### Short Scenario

An employee receives a restart prompt after a security update but keeps postponing it for two weeks because they do not want to interrupt their work.

**Ask learners:**

1. What is risky about this?
    
2. Why might the restart matter?
    
3. What should the employee do?
    
4. What should the manager support?
    

Expected answer:

The update may not be fully applied until restart. The employee should restart promptly at a suitable time, and the manager should support short downtime for security updates.

### Use Only Approved Devices and Software


### Short Scenario

An employee needs to compress a large customer file. They find a free online file-compression tool and upload the document.

Ask learners:

1. What is risky about this?
    
2. What should the employee have checked first?
    
3. What should they do if the file contained sensitive data?
    
4. What should the company provide to prevent this shortcut?
    

Expected answer:

The employee may have uploaded company data to an unapproved external service. They should have used an approved tool or asked IT. If sensitive data was uploaded, they should report it immediately. The company should provide approved tools for common file tasks.

### Protect Devices in and Outside the Office


### Evidence Leaders Should Request

Useful evidence includes:

- Device inventory
    
- Mobile device management report
    
- Encryption status report
    
- Endpoint protection coverage report
    
- Lost/stolen device procedure
    
- BYOD policy
    
- Remote-work policy
    
- Travel-security guidance
    
- Device return checklist
    
- Offboarding records
    
- Remote lock/wipe capability report
    

### Short Scenario

An employee works on a confidential client document at an airport. They leave their laptop open on the table while ordering coffee.

Ask learners:

1. What are the risks?
    
2. What should the employee have done?
    
3. What if the laptop is missing when they return?
    
4. What controls should leadership verify?
    

Expected answer:

The laptop could be viewed, used, stolen, or tampered with. The employee should have locked it and kept it physically with them. If missing, they should report immediately. Leadership should verify encryption, screen lock, endpoint protection, and remote lock/wipe capability.

### Recognize and Report Unusual Device Behavior


### Short Scenario

An employee’s browser starts opening strange tabs, their device becomes very slow, and a security warning appears after they downloaded a file from an email.

Ask learners:

1. What warning signs are present?
    
2. What should the employee stop doing?
    
3. What should the employee report?
    
4. What should they avoid doing?
    

Expected answer:

The warning signs include browser redirects, unusual slowness, a security alert, and a suspicious download. The employee should stop using the device for sensitive work and report immediately. They should not install cleanup tools, delete evidence, or keep working as normal.

### Vulnerability Scanning and Management


### Questions Leaders Should Ask

**Executives and key staff should ask:**

1. What systems are included in vulnerability scanning?
    
2. What systems are not included?
    
3. How often are scans performed?
    
4. Are internet-facing systems scanned more frequently?
    
5. How are critical vulnerabilities prioritized?
    
6. Do we use known-exploited vulnerability data?
    
7. Who owns remediation?
    
8. What are the deadlines for critical and high-risk issues?
    
9. Which vulnerabilities are overdue?
    
10. Are exceptions documented and time-limited?
    
11. Are fixes verified after remediation?
    
12. Are managed service providers reporting vulnerability status?
    
13. Are unsupported systems tracked and replaced?
    
14. Are vulnerability trends improving or getting worse?
    

### Evidence Leaders Should Request

Useful evidence includes:

- Asset inventory
    
- Vulnerability scan reports
    
- Scan coverage report
    
- Critical vulnerability list
    
- Known exploited vulnerability review
    
- Remediation timeline policy
    
- Overdue vulnerability report
    
- Assigned owner list
    
- Exception register
    
- Remediation verification records
    
- Unsupported system list
    
- Patch-compliance report
    
- Internet-facing asset report
    
- Managed service provider reports
    
- Vulnerability trend dashboard
    

Leadership should not accept a thick scan report as proof of security. The useful evidence is what was fixed, what remains open, who owns it, and what is overdue.



### Short Scenario

A vulnerability scan finds a critical issue on a public-facing remote access system. IT recommends an urgent update and a restart outside normal business hours. A manager wants to delay it for two weeks because the system is busy.

Ask learners:

1. Why is this high-risk?
    
2. What should management consider before delaying?
    
3. What should be documented if delay is unavoidable?
    
4. What should leadership verify afterward?
    

Expected answer:

The issue is high-risk because it affects a public-facing remote access system and may be exploitable by attackers. If delay is unavoidable, the risk should be documented, approved, mitigated where possible, and time-limited. Leadership should verify that the fix was completed and the vulnerability is closed.



### Leadership Assurance: Maintain Asset, Patch, and Vulnerability Management

Executives and key staff should ensure the company has:

- An inventory of devices, servers, applications, cloud services, and operating systems
    
- A process for identifying unsupported or end-of-life technology
    
- Automated patching where practical
    
- Defined deadlines for applying critical and high-risk updates
    
- Regular vulnerability scanning
    
- A process for prioritizing and remediating findings
    
- Named owners for remediation
    
- A process for approving, documenting, and expiring risk exceptions
    
- Secure configuration standards for important systems
    

CISA’s Cyber Essentials guidance specifically recommends automatic updates where possible, replacing unsupported technology, and deploying patches quickly. CIS Controls are also designed as a prioritized set of safeguards against prevalent attacks, with Implementation Group 1 positioned as a starting point for organizations of all sizes. ([CISA](https://www.cisa.gov/resources-tools/resources/cyber-essentials "Cyber Essentials"))

### Systems Hardening and Corrective Controls


### Short Scenario

An employee cannot install a personal productivity tool because company settings block it. The employee considers using a personal laptop and personal cloud storage to complete the task faster.

Ask learners:

1. What controls are being bypassed?
    
2. What risks does this create?
    
3. What should the employee do instead?
    
4. What should the manager do if the tool is genuinely needed?
    

Expected answer:

The employee would bypass software approval, device management, cloud storage controls, monitoring, and data protection. They should not use a personal workaround. They should request an approved tool or ask IT for a safe alternative. The manager should escalate the business need through the approved process.
