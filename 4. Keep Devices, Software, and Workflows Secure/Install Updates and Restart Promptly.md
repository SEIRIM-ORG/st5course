### Goals

Users should not delay software updates because flaws can give criminals access to files or accounts and keeping devices and apps up to date is one of the best ways to protect against malware and ransomware.

We discover why updates matter, why restarts may be required, why unsupported software is risky, and how to distinguish legitimate update instructions from fake update prompts.

### Learning Objective

By the end of this section, we will understand why updates matter, why restarts should not be delayed, and how employees can help keep company devices and software protected without needing to manage patching themselves.

Employees should learn this core behavior:

**Install approved updates promptly and restart when required.**

Managers and executives should learn this assurance principle:

**The company must know whether devices, applications, and systems are being updated on time.**

### Why This Matters

Software is never perfect. Operating systems, browsers, apps, phones, laptops, servers, and business tools may contain security flaws. Attackers look for those flaws and try to exploit them before organizations fix them.

Updates often include security patches that close these weaknesses. Delaying updates gives attackers more time to use known vulnerabilities.

**Updates may protect:**

- Laptops and desktops
    
- Phones and tablets
    
- Browsers
    
- Email clients
    
- Office applications
    
- Video meeting tools
    
- PDF readers
    
- Security software
    
- Business applications
    
- Cloud tools
    
- Routers and network devices
    
- Servers and databases
    

A device that is not updated can become an entry point into the company.

### Core Rule

When your company-approved device, software, or application asks for an update:

**Do not ignore it indefinitely. Do not keep clicking “remind me later.” Update promptly and restart when required.**

Some updates do not fully apply until the device or application restarts. If a restart is required and employees delay it for days or weeks, the device may remain exposed even though the update has been downloaded.

### What Employees Should Do

**Employees should:**

1. Allow approved updates to install.
    
2. Restart devices when required.
    
3. Follow company update deadlines.
    
4. Keep browsers and core work applications updated.
    
5. Keep mobile devices used for work updated.
    
6. Leave devices online long enough to receive updates.
    
7. Report update errors or repeated failed updates.
    
8. Avoid interrupting or disabling update processes.
    
9. Use only official app stores or approved company software sources.
    
10. Ask IT before installing updates from unfamiliar pop-ups or websites.
    

### What Employees Should Not Do

**Employees should not:**

- Delay updates for weeks
    
- Disable automatic updates
    
- Ignore restart prompts indefinitely
    
- Use unsupported software because it is familiar
    
- Install updates from suspicious links or pop-ups
    
- Download “urgent updates” from unknown websites
    
- Keep using an old device that can no longer receive security updates
    
- Assume updates are optional because the device still works
    

If a tool is too old to receive security updates, it may need to be replaced.

### Fake Update Warning

Attackers sometimes use fake update messages to trick users into installing malware.

**Be cautious if an update prompt:**

- Appears after clicking a suspicious link
    
- Comes from a random website
    
- Claims your browser or video player is urgently outdated
    
- Asks you to download a strange installer
    
- Uses pressure or scare language
    
- Does not come from the normal app, operating system, or company software tool
    

**Correct action:**

**Do not install updates from unfamiliar websites. Use official update settings or ask IT.**

### Why Restarts Matter

Many people delay restarts because they are busy. That is understandable, but risky.

**Restarts may be needed to:**

- Finish installing security patches
    
- Replace vulnerable files
    
- Restart protected services
    
- Apply browser or operating system updates
    
- Remove unstable or outdated components
    
- Complete endpoint protection updates
    

A restart is not just an inconvenience. In many cases, it is the final step that makes the update active.

### Manager Responsibilities

Managers should support update behavior instead of treating it as lost productivity.

**Managers should:**

- Encourage staff to install updates promptly
    
- Avoid penalizing employees for short update restarts
    
- Help schedule restarts around important work
    
- Make sure remote workers keep devices online for updates
    
- Escalate repeated update failures
    
- Discourage the use of unsupported tools or old devices
    
- Reinforce that security updates are part of normal work
    

Managers should not create a culture where employees feel they must avoid updates to stay productive.

### Executive and Key Staff Assurance Points

Executives and key staff do not need to install patches themselves across the company, but they do need to verify that patching is managed.

**Leadership should ensure the company has:**

- An inventory of devices, systems, and important software
    
- Automatic updates enabled where practical
    
- A defined timeline for applying critical updates
    
- Reporting on patch compliance
    
- A process for handling failed updates
    
- A process for replacing unsupported hardware or software
    
- Accountability for servers, cloud systems, laptops, mobile devices, and network equipment
    
- A way to identify systems that are not updating
    

NIST describes enterprise patch management as identifying, prioritizing, acquiring, installing, and verifying patches, updates, and upgrades across the organization. That last word matters: **verifying**. Leadership should not accept “we probably update things” as enough.

### Questions Leaders Should Ask

**Executives and key staff should ask:**

1. Do we have a current inventory of devices and software?
    
2. Are updates automatic where possible?
    
3. How quickly are critical security updates applied?
    
4. Which systems are currently behind on patches?
    
5. Who reviews patch-compliance reports?
    
6. Are remote devices receiving updates?
    
7. Are unsupported systems identified and replaced?
    
8. Are update failures tracked and fixed?
    
9. Are servers, network devices, and SaaS tools included?
    
10. Can IT prove updates were applied successfully?
    

### Evidence Leaders Should Request

**Useful evidence includes:**

- Device inventory
    
- Software inventory
    
- Patch-compliance report
    
- Critical update timeline
    
- List of unsupported software and hardware
    
- Failed update report
    
- Mobile device update status
    
- Server and network device patch status
    
- Exception register for delayed updates
    
- Replacement plan for end-of-life systems
    


### Key Takeaway

Updates close known weaknesses. Restarts often complete the protection.

Employees should install approved updates promptly, restart when required, and report update problems. Managers should support update behavior. Executives should verify that the company tracks patching, failed updates, unsupported systems, and critical update deadlines.

**An unpatched device is not just old. It may be an open door.**
