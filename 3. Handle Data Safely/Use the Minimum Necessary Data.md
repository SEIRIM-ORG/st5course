### Goal

This section highlights the **data-minimization** principle: reduce the amount of information collected, copied, shared, retained, or entered into tools so less sensitive data is exposed if something goes wrong. Data minimization helps lessen risk by reducing the personal information vulnerable to unauthorized access or use.

Teach staff to ask whether they need the information, whether the recipient needs all of it, and whether sensitive fields can be removed, masked, or summarized.

### Learning Objective

By the end of this section, we will understand how to reduce risk by using only the information needed for a specific task. Employees should be able to identify when they are collecting, copying, sharing, exporting, uploading, or retaining more data than necessary.

Employees should learn this core behavior:

**Use the least amount of sensitive information needed to complete the task safely.**

Managers and executives should learn this assurance principle:

**The company should limit unnecessary collection, access, sharing, retention, and movement of sensitive data.**

### Why This Matters

Sensitive information creates risk wherever it exists.

The more data the company collects, copies, exports, emails, stores, uploads, or shares, the more damage can occur if something goes wrong.

**A data breach is not always caused by an attacker breaking into a system. It can also happen when an employee:**

- Sends a full spreadsheet when only one row was needed
    
- Shares an entire folder when one file was needed
    
- Copies customer data into an unapproved tool
    
- Uploads confidential information into a public AI service
    
- Forwards a long email thread containing old sensitive details
    
- Downloads records to a laptop and forgets to delete them
    
- Keeps old exports “just in case”
    
- Gives a vendor more data than the vendor needs
    
- Includes real customer or employee data in a test file
    
- Leaves unnecessary sensitive data in screenshots or presentations
    

The safest data is data that does not need to be exposed in the first place.

### Core Rule

Before collecting, sending, uploading, copying, or storing information, ask:

**What is the minimum information needed to complete this task?**

Then use only that.

**Minimum necessary data means:**

- Fewer records
    
- Fewer fields
    
- Fewer recipients
    
- Less detail
    
- Shorter retention
    
- Lower permissions
    
- Safer formats
    
- Approved systems only
    
- Redacted or masked data where possible
    

The goal is not to make work difficult. The goal is to avoid exposing information that does not need to be involved.

### What “Minimum Necessary” Means

Minimum necessary means using enough information to complete the task, but not more.

**For example:**

- If someone needs a total number, do not send the full customer list.
    
- If someone needs to review one contract, do not share the entire legal folder.
    
- If a vendor needs delivery details, do not include customer payment information.
    
- If a team needs a sample, do not use real personal data unless required and approved.
    
- If an AI tool needs a summary, do not paste names, account numbers, financial details, or confidential strategy.
    
- If a manager needs to approve an expense, do not send unrelated employee records.
    

The question is not only “Can I send this?”

**The better question is:**

**Does this person, system, or tool need all of this information?**

### Where Over-Sharing Happens

Over-sharing often happens during ordinary work.

**Common examples include:**

#### 1. Spreadsheets

Spreadsheets are high-risk because they often contain more data than the sender realizes.

**Risky behavior:** - Sending the entire spreadsheet when only a small section is needed.

**Safer behavior:** - Remove unnecessary rows, columns, tabs, hidden fields, comments, and formulas before sharing.

#### 2. Email Threads

Long email threads may contain old attachments, pricing, legal advice, customer data, or internal comments.

**Risky behavior:** - Forwarding the full thread to an external recipient.

**Safer behavior:** - Start a new message and include only the information needed.

#### 3. Cloud Folders

Cloud folders may contain many documents unrelated to the recipient’s task.

**Risky behavior:** - Sharing an entire folder with external users.

**Safer behavior:** - Share only the specific file needed, with the lowest appropriate permission.

#### 4. Screenshots

Screenshots often capture extra information in the background.

**Risky behavior:** - Sharing a screenshot that includes customer names, internal notes, financial details, or open browser tabs.

**Safer behavior:** - Crop, blur, redact, or recreate the information without sensitive details.

#### 5. AI Tools

AI prompts can expose data if employees paste too much context.

**Risky behavior:** - Uploading a full customer complaint file into an unapproved AI tool.

**Safer behavior:** - Use approved AI tools and remove names, account numbers, confidential details, and unnecessary context.

#### 6. Test and Demo Data

Real data is often copied into test, demo, or training environments.

**Risky behavior:** - Using real customer, employee, or financial data when fake data would work.

**Safer behavior:** - Use synthetic, anonymized, or reduced data whenever possible.

#### 7. Vendor Requests

Vendors may request more data than they actually need.

**Risky behavior:** - Sending full records because the vendor asked for them.

**Safer behavior:** - Confirm the purpose and provide only the fields necessary for that purpose.

### The Minimum Necessary Data Checklist

**Before sharing or using data, ask:**

1. What is the purpose?
    
2. What exact information is needed?
    
3. Can I remove names, IDs, addresses, account numbers, or financial details?
    
4. Can I send a summary instead of raw data?
    
5. Can I send fewer rows or fewer records?
    
6. Can I remove hidden tabs, columns, formulas, or comments?
    
7. Can I use view-only access instead of sending a copy?
    
8. Can access expire after the task is complete?
    
9. Can fake, masked, or anonymized data be used?
    
10. Is the recipient approved to receive this information?
    
11. Is the tool approved to process this information?
    
12. How long does this information need to be kept?
    

If the task can be completed with less data, use less data.

### Practical Data Reduction Techniques

#### 1. Remove Unnecessary Fields

If the recipient does not need a field, remove it.

Examples of fields to remove when unnecessary:

- Names
    
- Addresses
    
- Email addresses
    
- Phone numbers
    
- Account numbers
    
- Government IDs
    
- Dates of birth
    
- Salary details
    
- Bank details
    
- Internal notes
    
- Security details
    
- Pricing formulas
    

#### 2. Send a Summary Instead of Raw Data

Sometimes a person needs an answer, not the underlying data.

**Example:**

Instead of sending a full customer list, send:

“43 customers were affected, all from the West region, with no payment data involved.”

#### 3. Mask or Redact Sensitive Values

Masking means hiding part of the information.

**Examples:**

- Show only the last four digits of an account number.
    
- Replace names with initials.
    
- Remove customer IDs.
    
- Blur personal details in screenshots.
    
- Replace exact values with ranges where appropriate.
    

#### 4. Use Aggregated Data

Aggregated data groups information so individual people or records are not exposed.

**Example:**

Instead of sending each employee’s salary, send average salary by department if that is enough for the task.

#### 5. Use Synthetic or Test Data

Synthetic data is fake data that resembles real data but does not identify real people, customers, or transactions.

**Use it for:**

- Training
    
- Software testing
    
- Product demos
    
- Screenshots
    
- Vendor trials
    
- AI experiments
    
- Process documentation
    

#### 6. Limit Recipients

Do not send sensitive information to a large group if only one or two people need it.

**Before sending, check:**

- To
    
- CC
    
- BCC
    
- External domains
    
- Distribution lists
    
- Shared mailbox recipients
    
- Group memberships
    

#### 7. Use Access Instead of Copies

When possible, provide controlled access instead of sending a file copy.

A file copy can be downloaded, forwarded, saved, or lost.

**Controlled access can often be:**

- View-only
    
- Revoked
    
- Expired
    
- Audited
    
- Limited to named users
    

#### 8. Limit Retention

Do not keep sensitive data longer than needed.

**Examples:**

- Delete temporary exports after use.
    
- Remove old downloaded reports.
    
- Close access after a project ends.
    
- Clean up obsolete folders.
    
- Do not keep duplicate copies “just in case.”
    

### What Employees Should Do

**Employees should:**

1. Use only the data needed for the task.
    
2. Remove unnecessary fields before sharing.
    
3. Share summaries instead of raw data when possible.
    
4. Use fake, masked, or anonymized data for testing and demos when possible.
    
5. Check hidden tabs, comments, columns, and metadata before sending files.
    
6. Avoid forwarding long email threads without review.
    
7. Share specific files instead of entire folders.
    
8. Use view-only access when editing is not required.
    
9. Limit external recipients.
    
10. Use approved systems for sensitive data.
    
11. Delete temporary exports when no longer needed.
    
12. Ask before uploading sensitive data into AI or third-party tools.
    

### What Employees Should Not Do

Employees should not:

- Send full datasets when a summary is enough
    
- Share whole folders when one file is enough
    
- Include sensitive data in screenshots unnecessarily
    
- Copy customer or employee data into personal notes
    
- Paste confidential information into unapproved AI tools
    
- Export large reports without a clear need
    
- Keep old exports indefinitely
    
- Send spreadsheets without checking hidden data
    
- Use real data for training or testing when fake data would work
    
- Share sensitive data with vendors without confirming the business need
    
- Assume that more information is always better
    
- Retain duplicate copies because they might be useful later
    

### Minimum Necessary Data and AI Tools

AI tools create a specific over-sharing risk because users often paste large amounts of context to get a better answer.

Employees should not paste sensitive information into AI tools unless the tool is approved and the data type is allowed.

**Before using AI, ask:**

1. Is this AI tool approved by the company?
    
2. Does the prompt contain personal, customer, HR, financial, legal, security, or confidential information?
    
3. Can I remove names, numbers, and identifiers?
    
4. Can I ask the question using a generic example?
    
5. Can I summarize the issue without sharing the raw data?
    
6. Is there a company-approved safer method?
    

**Unsafe AI prompt:**

“Summarize this customer complaint,” followed by the customer’s name, account number, contract terms, internal notes, and payment history.

**Safer AI prompt:**

“Summarize this generic customer complaint scenario. Remove personal details and focus only on the service issue.”

### Minimum Necessary Data and Vendors

Vendors and third parties should receive only the data they need to perform the approved service.

**Before sending data to a vendor, ask:**

- What service are they providing?
    
- What exact data fields do they need?
    
- Do they need real data or would test data work?
    
- Do they need all records or only a sample?
    
- Is the vendor approved to receive this data?
    
- Is there a contract or data-processing requirement?
    
- How will the vendor store, protect, and delete the data?
    
- Who approved the transfer?
    

Do not send full datasets to vendors simply because it is easier.

### Minimum Necessary Data and Internal Teams

Internal sharing still requires judgment. Not every employee needs access to every internal file.

**Examples:**

- Finance may not need HR medical leave details.
    
- Sales may not need full customer payment records.
    
- Marketing may not need raw customer personal data.
    
- Operations may not need employee salary information.
    
- Managers may need trend summaries rather than individual records.
    

“Internal” does not mean “available to everyone.”

### Manager Responsibilities

Managers should make minimum necessary data a normal team habit.

Managers should:

- Teach teams which data fields are required for common tasks
    
- Challenge reports or exports that include unnecessary data
    
- Ensure vendors receive only approved data
    
- Encourage summaries and redacted files where possible
    
- Require review before sending sensitive data externally
    
- Limit team folder access to current business needs
    
- Remove old exports and duplicate files from shared spaces
    
- Use synthetic data for training or testing where possible
    
- Make sure AI use follows company rules
    
- Support employees who slow down before sending sensitive data
    

Managers should not ask staff to “just send everything” when only part of the information is needed.

### Executive and Key Staff Assurance Points

Executives and key staff should verify that the company is not collecting, storing, or spreading sensitive data unnecessarily.

Leadership should ensure the company has:

- A simple data classification model
    
- Data owners for important information
    
- Approved storage locations
    
- Rules for external data sharing
    
- Rules for AI tool use
    
- Rules for vendor data transfers
    
- Retention and deletion procedures
    
- Controls over bulk exports
    
- Access reviews for sensitive data repositories
    
- Guidance for masking, redaction, and anonymization
    
- Secure disposal of old files and reports
    
- Periodic review of where sensitive data is stored
    

The leadership question is:

**Are we using only the data we need, or are we creating unnecessary exposure?**

### Questions Leaders Should Ask

Executives and key staff should ask:

1. What sensitive data do we collect, and why?
    
2. Are we collecting more data than we need?
    
3. Are employees exporting full datasets unnecessarily?
    
4. Are vendors receiving more data than required?
    
5. Are old reports, exports, and backups retained longer than necessary?
    
6. Are sensitive files duplicated across too many locations?
    
7. Are employees using real data for testing, demos, or training?
    
8. Are AI tools being used with sensitive data?
    
9. Do employees know how to redact or mask data?
    
10. Are external sharing and bulk downloads monitored?
    
11. Are retention rules defined and followed?
    
12. Who owns cleanup of old sensitive data?
    
13. Can we prove that unnecessary data is deleted or archived securely?
    
14. Are access rights aligned with minimum necessary data use?
    

### Evidence Leaders Should Request

Useful evidence includes:

- Data retention policy
    
- Data classification policy
    
- Data inventory
    
- Approved storage location list
    
- Bulk export logs
    
- External sharing reports
    
- Vendor data-sharing records
    
- AI use policy
    
- Redaction or anonymization guidance
    
- Access review reports
    
- Reports of old or duplicate sensitive data
    
- Records of deleted or archived data
    
- Data owner list
    
- Incident reports involving over-sharing
    
- Evidence of cleanup actions after data reviews
    

Leadership should not accept “we are careful with data” as enough. They should ask whether unnecessary data exposure is being actively reduced.

### Warning Signs of Poor Data Minimization

The company may have a problem if:

- Employees routinely send full spreadsheets externally
    
- Teams keep old exports indefinitely
    
- Sensitive data is copied into many tools
    
- Vendors receive full datasets without review
    
- Real customer data is used in demos or testing
    
- AI tools are used without clear data limits
    
- Shared folders contain years of old confidential files
    
- Reports include personal data that is not needed
    
- Screenshots expose extra information
    
- Long email threads are forwarded casually
    
- Employees do not know what data can be removed
    
- Nobody owns retention or cleanup
    

These are not minor hygiene issues. They increase breach impact.

### Examples

#### Example: The Full Spreadsheet

A manager asks an employee to send a vendor a spreadsheet so the vendor can confirm shipment quantities.

**The spreadsheet includes:**

- Customer names
    
- Delivery addresses
    
- Internal pricing
    
- Margin notes
    
- Supplier comments
    
- Payment status
    
- Shipment quantities
    

The vendor only needs shipment quantities and delivery regions.

**Unsafe action:**

Send the full spreadsheet.

**Safer action:**

Create a reduced version containing only the shipment quantity and delivery region fields. Remove customer names, pricing, margin notes, and payment status.

#### Example: The AI Draft

An employee wants to use an AI tool to rewrite a customer complaint response. They paste the entire support ticket into the tool.

The ticket includes:

- Customer name
    
- Email address
    
- Account ID
    
- Contract details
    
- Internal escalation notes
    
- Refund discussion
    

**Unsafe action:**

Paste the full ticket into an unapproved AI tool.

**Safer action:**

Use an approved AI tool if available and remove identifying details. Ask the AI to help rewrite a generic version of the response without customer-specific information.

#### Example: The External Consultant

A consultant asks for “all relevant HR data” to help review employee turnover.

**Unsafe action:**

Send the full HR export with names, salaries, bank details, performance notes, and disciplinary records.

**Safer action:**

Clarify the purpose. Provide only the fields needed for turnover analysis, such as department, role type, hire date, departure date, and anonymized employee ID, if approved.

#### Example: The Screenshot

An employee takes a screenshot of a dashboard to show a system error.

The screenshot also includes customer names, revenue values, and open internal chat messages.

**Unsafe action:**

Send the screenshot as-is.

**Safer action:**

Crop or blur unrelated sensitive information before sending it through the approved support channel.

### Key Takeaway

Using sensitive information safely is not only about protecting it after it is shared. It is also about reducing how much information is exposed in the first place.

Employees should use only the data needed for the task. Managers should challenge unnecessary exports, copies, and broad sharing. Executives should verify that the company has practical controls for collection, retention, vendor sharing, AI use, and deletion.

**The less unnecessary data you expose, the less damage a mistake or attack can cause.**
