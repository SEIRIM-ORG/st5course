## Use Strong Passwords and Save them Securely!

Current guidance supports the use of long, unique passwords; avoid password reuse; use password managers to generate and store them; pair passwords with MFA; and stop relying on outdated “complexity formula” advice. 

NIST’s current password guidance says passwords are not phishing-resistant, requires longer minimums for single-factor passwords, rejects composition rules like mandatory symbols/capitals, and discourages routine forced password changes unless compromise is suspected.

### Learning Objective

By the end of this section, learners should understand why weak or reused passwords create business risk, how password managers reduce that risk, and what actions employees, managers, and executives should take to make password use safer across the organization.

### Why This Matters

Passwords are still one of the most common ways employees access email, cloud platforms, business applications, financial systems, HR systems, file storage, and customer data.

If a password is weak, reused, shared, stored carelessly, or stolen through phishing, an attacker may be able to enter company systems using a real employee account. That is especially dangerous because activity from a valid account may look legitimate at first.

**A stolen password can allow an attacker to:**

- Read company email
    
- Send messages pretending to be the employee
    
- Reset other account passwords
    
- Access files and cloud storage
    
- Steal customer or employee data
    
- Approve fake requests
    
- Add forwarding rules
    
- Access financial or operational systems
    
- Move deeper into the company network
    

The business risk is not only “someone guessed a password.” The real risk is that an attacker gains trusted access and uses it to commit fraud, steal data, or disrupt operations.

### Core Rule

Every important account should use a strong, unique password managed securely through an approved password manager.

**The simplest rules for employees is:**

- Do not reuse passwords
- Do not share passwords
- Do not store passwords in unsafe places
- Use the approved password manager

### What Makes a Password Strong?

**A strong password is:**

- Long enough to resist guessing and increase possibilities (entropy) and difficulty to crack. While legacy guidance often cited 8 characters as a baseline, current NIST recommendations emphasize a **minimum of 15 characters** for robust security. For reference, systems should support passwords up to **64 characters** to accommodate longer, more secure passphrases.
    
- Unique to one account
    
- Not based on personal information
    
- Not reused from another website or system
    
- Not a common phrase or predictable pattern
    
- Not stored in an unsafe location
    
- Protected by MFA wherever possible
    

**The most important point is uniqueness.**

A password that is strong but reused is still dangerous. If the password is stolen from one service, attackers may try it against email, cloud storage, banking, business software, and other accounts.

### Weak Password Habits to Avoid

**Employees should avoid:**

- Reusing the same password across work and personal accounts
    
- Using small variations of the same password
    
- Using names, birthdays, pets, sports teams, or company names
    
- Using predictable changes such as “Password2025!” and then “Password2026!”
    
- Writing passwords on sticky notes near the computer
    
- Saving passwords in spreadsheets or documents
    
- Sending passwords through email or chat
    
- Sharing passwords with coworkers
    
- Using a personal password manager if the company requires an approved business tool
    
- Saving work passwords on shared or public devices
    
- Saving critical passwords in unsecured browsers or such weakly protected spaces
    

 
A password is not safe just because it has a capital letter, number, and symbol. Predictable passwords with minor substitutions are still weak.

**Example:**

“CompanyName2026!” may look complex, but it is predictable.

A password manager can create something much stronger because the employee does not need to memorize it.

### Why Password Managers Matter

Most employees cannot remember a different strong password for every account. That is normal. The solution is not to force people to memorize dozens of complex passwords. The solution is to use a password manager.

**A password manager helps employees:**

- Create strong passwords
    
- Store unique passwords securely
    
- Avoid password reuse
    
- Autofill passwords on the correct website
    
- Reduce typing errors
    
- Detect weak or reused passwords
    
- Warn about some exposed or compromised passwords
    
- Share credentials securely when approved by company policy
    

The key benefit is that employees no longer need to invent, remember, or manually track passwords for every service.

### The Master Password

A password manager is protected by a primary password, sometimes called a master password.

**This password must be:**

- Long
    
- Unique
    
- Memorable to the employee
    
- Not reused anywhere else
    
- Not shared with anyone
    
- Protected with MFA where available
    

Employees should understand that this is one of the most important passwords they have. If the company uses single sign-on or another approved login method for the password manager, employees should follow the company’s setup instructions exactly.

### Password Manager Autofill and Phishing

Password managers can also help reduce phishing risk.

If an attacker creates a fake login page, the password manager may not autofill the password because the website address does not match the legitimate site.

This is not a perfect defense, but it is a useful warning sign.

If a password does not autofill on a page where it normally does, employees should stop and inspect the website before entering anything manually.

### What Employees Should Do

**Employees should:**

1. Use the company-approved password manager.
    
2. Create a strong and unique password for every work account.
    
3. Never reuse work passwords for personal accounts.
    
4. Never reuse personal passwords for work accounts.
    
5. Protect the password manager with MFA where available.
    
6. Never share passwords through email, chat, documents, or spreadsheets.
    
7. Never approve browser password saving on shared or public devices.
    
8. Change a password immediately if instructed by security or if compromise is suspected.
    
9. Report suspicious login prompts, password reset emails, or password manager warnings.
    
10. Use passkeys when the company makes them available and approved.
    

### Learning Examples:

#### Example: Password Reuse Attack

An employee uses the same password for a personal shopping account and their work email.

The shopping website is breached. Attackers obtain the employee’s email address and password from that breach. They then try the same password against the employee’s work email.

If the employee reused the password, the attacker may gain access to the work account.

**Once inside the work email, the attacker may:**

- Read confidential messages
    
- Send phishing emails internally
    
- Reset other account passwords
    
- Search for invoices or banking details
    
- Set up hidden forwarding rules
    
- Impersonate the employee to customers or coworkers
    

The original breach did not happen inside the company, but the company still becomes exposed because of password reuse.

#### Example: Unsafe Password Sharing

A team shares one login for a business tool because it is convenient.

**This creates several problems:**

- Nobody knows who performed an action
    
- The password may be copied or stored unsafely
    
- Former employees may still know the password
    
- MFA may be bypassed or weakened
    
- The company cannot properly remove access when someone leaves
    
- An incident becomes harder to investigate
    

Shared passwords may feel efficient, but they create accountability and security problems.

The better solution is individual accounts with appropriate access levels.

#### Example: Password Stored in a Spreadsheet

A department stores system passwords in a shared spreadsheet.

**This is risky because:**

- Too many people may access the file
    
- The file may be downloaded or copied
    
- Permissions may be misconfigured
    
- The spreadsheet may be emailed externally by mistake
    
- Former staff may retain access
    
- The file may be exposed if one account is compromised
    

The safer approach is to use an approved password manager with controlled sharing, access logs, and MFA.

#### Strong Password Decision Rule

**Employees should ask:**

- Is this password unique?
    
- Is it stored only in the approved password manager?
    
- Is it protected by MFA where possible?
    
- Is it impossible for a coworker, attacker, or family member to guess?
    
- Would this password expose other accounts if it were stolen?
    

If the answer is no, the password is not acceptable.

### Passwords and MFA Work Together

A strong password is important, but it is not enough by itself.

**Passwords can be stolen through:**

- Phishing
    
- Malware
    
- Data breaches
    
- Fake login pages
    
- Password reuse
    
- Shoulder surfing
    
- Unsafe storage
    
- Compromised personal accounts
    

MFA adds another layer of protection. If an attacker steals a password, MFA can make it harder for them to access the account.

However, employees must also use MFA correctly. They should never approve a login prompt they did not initiate and should never share MFA codes.

### Passkeys

Where available and approved by the company, passkeys can reduce password risk.

A passkey allows the user to sign in using a device-based method such as a fingerprint, face check, PIN, or security key. Passkeys are harder to phish than ordinary passwords because the user is not typing a reusable secret into a website.

Employees do not need to master the technical details. The practical rule is:

**If the company offers passkeys for an approved system, use them according to company instructions.**

### Manager Responsibilities

Managers should make sure their teams do not create unsafe password workarounds.

Managers should:

- Ensure staff use the approved password manager
    
- Discourage password sharing
    
- Avoid asking employees to share credentials for convenience
    
- Make sure new staff receive password manager setup support
    
- Make sure departing staff lose access promptly
    
- Escalate any need for shared access to IT or security
    
- Report any team spreadsheet, document, or chat thread containing passwords
    
- Reinforce that passwords and MFA codes are never to be shared
    

Managers should not normalize insecure shortcuts.

If a team believes it needs a shared login, that is usually a sign the business process or licensing model needs to be fixed.

### Executive and Key Staff Assurance Points

Executives and key staff do not need to configure password systems themselves, but they should verify that the company has a controlled password and access-management approach.

**Leadership should verify that:**

- The company has an approved password manager
    
- Staff are trained to use it
    
- Password reuse is discouraged and monitored where possible
    
- MFA is required for critical systems
    
- Password manager access is protected with MFA
    
- Shared accounts are identified and reduced
    
- Admin accounts have stronger controls
    
- Former employee access is removed promptly
    
- Passwords are not stored in spreadsheets, documents, or shared drives
    
- Password policies are practical and aligned with current guidance
    
- Password resets and account recovery follow secure verification procedures
    


### Evidence Leaders Should Request

**Useful evidence includes:**

- Password manager deployment report
    
- MFA coverage report
    
- List of systems not yet covered by MFA
    
- Shared-account inventory
    
- Privileged-account inventory
    
- Offboarding checklist
    
- Password reset procedure
    
- Account recovery procedure
    
- Training completion records
    
- Policy on password sharing and credential storage
    
- Records of password-related incidents or near misses
    

Leadership should not accept “we have a password policy” as enough. They should ask whether the policy is usable, enforced, and supported by the right tools.

### Common Misconceptions

#### Misconception 1: “A complex password is always safe.”

Not necessarily. A complex password that is reused is dangerous.

#### Misconception 2: “Changing passwords every few months automatically improves security.”

Routine forced changes can lead users to create weaker patterns. Password changes are most important when compromise is suspected or confirmed.

#### Misconception 3: “It is fine to share a password if the team trusts each other.”

Shared passwords remove accountability and make access harder to control.

#### Misconception 4: “Saving passwords in a browser is always unsafe.”

Saving passwords on a trusted, company-managed device may be acceptable if company policy allows it. Saving passwords on shared or public devices is not acceptable.

#### Misconception 5: “MFA means passwords no longer matter.”

MFA reduces risk, but passwords still matter. Attackers can still exploit weak passwords, reused passwords, phishing, or MFA fatigue.

### Key Takeaway

Strong password security is not about memorizing complicated formulas. It is about using unique passwords, storing them safely, avoiding reuse, and protecting important accounts with MFA.

Employees should use the approved password manager. Managers should stop unsafe password workarounds. Executives should verify that the company has password management, MFA, and access controls operating in practice.

**One reused password can become the doorway into the company.**
